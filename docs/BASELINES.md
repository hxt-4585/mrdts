# 基线方法与历史效果

记录日期：2026-11-06。本文保留基线的设计与实验结论，供后续 Codex 接手；即使部分代码、结果或聊天记录被删除，也不要把“文件不存在”理解为“从未实现”。以下数字来自保存的历史实验，未重新训练或评估。根 README 和 PROJECT_STRUCTURE 中“没有训练入口、奖励未实现”的旧描述已过时。

## 共通设计

Master 高层负责 Member UAV 的二维飞行动作，Member 低层负责 DAG 子任务的执行位置（同区域 Member、BS 或用户本地设备）。子任务顺序基本采用 ERS，不由 PPO 学习排序。

HMAPPO 与冻结低层 PPO 的高层奖励为负的归一化系统平均 DAG 时延，另扣越界惩罚；低层使用子任务等待、传输、排队和计算时间构成的归一化时延奖励。能耗目标主要由 local_surrogate 显式引入。

冻结低层的高层对照方法默认使用 random_uav_ppo 的第 371 轮低层权重，冻结后采用合法动作掩码下的 argmax；环境配置从低层检查点恢复。它们用于固定调度能力后比较高层方法。

## 方法与实现

方法入口为 `methods/<名称>/run.py`，配置为 `config/methods/<名称>.toml`。

| 名称 | 是什么、如何实现 |
|---|---|
| random | 无训练的随机对照。每时隙随机采样 UAV 飞行动作，ERS 排序后，在合法执行节点中随机放置子任务。 |
| hmappo | 分层联合 PPO。Master 共享 Actor、使用集中式 Critic；每架 Member 独立 Actor 和局部 Critic。默认联合学习飞行与执行位置，也支持 member 预训练、冻结低层训练 master 两个阶段。 |
| random_uav_ppo | 随机飞行下只训练低层。无 Master 网络；每架 UAV 默认每 10 时隙重新采样二维动作，中间保持向量，外边界处反向。每架 Member 独立 PPO，是其他高层基线的低层预训练来源。 |
| frozen_member_ppo | 冻结 Member，只用 PPO 学习 Master 的逐时隙飞行动作。保留共享 Actor、集中式 Critic，跨时隙计算 GAE；低层不更新。 |
| local_surrogate | 冻结低层的局部代理搜索。各区域使用随机 Fourier 特征和递推岭回归，在线预测区域时延及非飞行能耗；飞行能耗直接计算。利用本区域与一跳邻居信息，搜索候选动作并交换标量报价，优化归一化 Q 加权能耗与时延，加启发式不确定性惩罚。只从实际执行反馈学习，不对每个候选调用完整仿真。 |
| delay_surrogate | local_surrogate 的纯时延对照。保留局部特征、候选搜索和邻居报价，只学习区域时延；评分不使用 Q 或能耗，保留时延预测不确定性惩罚。 |
| centralized_cem | 集中式静态部署搜索。CEM 对所有 UAV 的归一化目标位置采样，仿真评价平均时延，选择精英并更新分布；用独立验证任务流选择部署。UAV 从初始位置按速度限制飞向目标，到达后保持。 |
| waypoint_mappo | 用 MAPPO 学习静态目标点。各 Master 根据局部初始观测产生所属 UAV 的目标位置，共享集中式价值函数与团队回报；一次联合部署是一条终止转移，以短程仿真平均时延的负值训练。不是逐时隙反馈的动态轨迹策略。 |
| centralized_ppo | 独立实现的集中式联合动作 PPO。单个 Actor 读取全局初始位置及用户布局，输出全部 UAV 的目标位置；一次部署构成终止动作，以完整回合平均 DAG 时延的负值训练。联合 log-prob、镜像采样、排除同一对样本的回报基线与高斯 KL 回溯约束用于稳定更新。冻结低层，独立实现 ERS 与推理，不导入其他基线；不使用 CEM 部署初始化或模仿。验证集选择确定性 Actor，CEM 权重中的目标点只在最终对照测试时读取。 |

局部代理搜索目前通过单进程顺序模拟邻居协议，不代表真实并行加速或全局最优，也没有严格能量稳定性保证。静态部署方法不能直接等同于动态飞行策略。

### centralized_ppo 的实验协议与入口

默认训练 200 次更新，每次 12 对镜像部署，共 24 次完整 500 时隙仿真；每次更新所有部署共享一个训练任务流，更新之间更换任务流。训练 epoch 为 300000 起连续 10000 个，验证为 1000000—1000002，最终测试为 2000000—2000009。第 0、1 次以及每 5 次更新验证一次，验证周期与运行结束点无关，续训不会额外增加选择候选。训练预算约 240 万时隙，比原 60 代 CEM 大，时延比较不代表样本效率持平。

高层状态仅包含 12 架 UAV 的初始二维位置和 30 个用户的二维位置，均除以场景边长，总计 84 维；不输入区域编号。Actor 为 `84 → 64 → 64 → 24`。此前 126 维版本的训练在第 7 次更新采样期间因状态修订而停止，保留结果于 `results/centralized_ppo/launches/20261106T204635_2768908/run/`，完成了 6 次更新，最佳验证时延 0.351597 秒，未执行最终测试。84 维版本重新训练，不能直接续用旧输入层检查点。

```powershell
uv run python -B -m methods.centralized_ppo.run
# 后台正式训练并注册 Windows 每 30 分钟监控
powershell -NoProfile -ExecutionPolicy Bypass -File methods/centralized_ppo/launch.ps1
# 临时探索只看验证集，避免提前暴露最终测试集
uv run python -B -m methods.centralized_ppo.run --updates 20 --skip-test
uv run python -B -m methods.centralized_ppo.run --resume-from <运行目录> --updates 200
# 在新的配对任务流上评估已选 Actor；默认不覆盖原测试结果
uv run python -B -m methods.centralized_ppo.evaluate <运行目录> --epoch-start 2100000
```

`latest.pt` 保存策略、优化器、随机状态和训练进度；`best.pt` 保存验证最优的神经策略。续训继承跳过最终测试的设置，可用独立 evaluate 入口完成最终评估。查看过测试结果后继续调参，原测试集不能再作为新方案的独立留出集。`test_results.json` 包含 PPO、原 60 代 CEM、悬停及随机飞行的配对结果；同时报告均值、失败率、时延差的 episode bootstrap 区间，以及 `PPO时延 - 1.01×CEM时延` 的配对区间，区分点估计达到 1% 容差与区间支持该结论。

长训练应在本地后台启动，并注册 Windows 定时任务每 30 分钟调用 `methods.centralized_ppo.monitor`；监控记录在运行目录的 `monitor.json` 与 `monitor_history.jsonl`，训练结束后写 `completion.txt` 并停用对应任务。监控只记录状态，不修改策略或根据测试结果调参。

### waypoint_mappo 的关键对照

两次均为 seed=45，每次更新采样 12 个部署，训练评价长度 48 时隙；测试均使用 epoch 2000000、2000001，每回合 500 时隙，共 30,000 DAG，相同冻结低层。

| 策略 | 测试平均时延 | 失败率 |
|---|---:|---:|
| 初始策略 | 0.3448 | 0% |
| 悬停 | 0.3644 | 0% |
| 随机飞行 | 0.3636 | 0.31% |
| 8 次更新后的策略 | 0.2932 | 0% |
| 200 次更新后的策略 | 0.4558 | 6.02% |

200 次更新实验的训练采样平均时延由 0.3873 降至 0.2901，但长程测试变差。48 时隙训练与 500 时隙测试之间的差异是待排查因素，具体退化原因尚未确认。不要仅凭训练奖励曲线判断部署效果或收敛。
