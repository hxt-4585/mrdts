# ERS Delay Implementation Plan

> **For agentic workers:** Execute this approved plan inline, task by task, with failing tests before each behavior change.

**Goal:** Implement core-weighted, relay-aware delay ERS and preserve its multi-DAG order in actual execution.

**Architecture:** ERS reads the current runtime candidate set, core frequencies, RoutePlanner and shared hop-duration method. It returns inspectable costs and a deterministic order; external placement choices enter one atomic batch before dispatch.

**Tech Stack:** Python 3.11, NumPy, unittest; no new dependencies.

## Global Constraints

- Preserve existing unrelated workspace edits.
- No energy virtual queue, placement optimizer or input-upload term in rank.
- KB means 1024 bytes. Physical cores share their device's links and energy accounting.
- Preserve current local FIFO, region restrictions and deadline lifecycle.
