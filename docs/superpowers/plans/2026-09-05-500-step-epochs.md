# 500-step epoch training

User request: epoch-reward plots and 500 steps per epoch, each step comprising
Master command plus all Member DAG scheduling. Preserve all previously existing
files; implement in new modules and entry points on the current feature branch.

Definitions: an environment step is one Master flight batch, topology refresh,
100 default DAGs scheduled by Members, actual execution, and one global reward.
An epoch resets physical positions once, then executes exactly 500 such steps.
`ppo_epochs` is optimizer passes over a rollout, not environment steps or epochs.
Epoch logs record sum(reward), mean(reward), step count and cumulative steps.

Keep staged optimization to limit nonstationarity. In Member epochs Master acts
using its frozen deterministic policy every step; Member samples and learns. In
Master epochs Member acts using its frozen deterministic policy every step; Master
samples and learns. Frozen means no updates, not skipping the forward action.

Member buffers are bounded by `update_every_steps` (default 8). A full epoch with
500000 subtask decisions must not be buffered at once. Buffer flushes never reset
positions or the epoch clock. Member placement returns remain per-slot terminal
returns: its actions cannot affect future queues, physical movement or workloads
under the current default environment and frozen Master observation contract.
Master trajectories (500 x 4 samples) fit in memory, so update at true epoch end;
retain the existing gamma=1, lambda=.95 GAE and raw per-step global rewards.

Use a new EpochLearner checkpoint format; add normalized remaining-epoch time to
the Master critic so finite-horizon value has time context. Keep the existing
actors and Member critic architecture. Save both current and best checkpoints.
Reserve validation/test DAG prefixes using their actual macro-step counts. Resume
at completed epoch boundaries with optimizer and RNG state; disallow changing the
episode length during resume. No implicit warm start from the older 8-slot runs.
