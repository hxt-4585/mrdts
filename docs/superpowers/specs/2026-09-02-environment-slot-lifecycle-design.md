# 环境时隙生命周期

## 已确认目标

将用户确认的“飞行、刷新拓扑、新建运行时、窗口结束统计并丢弃”落实为环境接口。保留现有完整 DAG placement 和 ERS 算法；本次不实现策略、奖励、能量虚拟队列或训练 reset/step。

## 接口与状态

- `Environment.begin_slot(region, user_positions, normalized_actions)`：仅在无活动时隙时调用，返回逐 Member 的越界布尔数组。先执行飞行，再调用不依赖 runtime 的 `refresh_slot_topology(region, user_positions)`，最后创建运行时并放到只读属性 `environment.runtime`。开始失败恢复物理状态；重复开始在飞行前报错。
- `Environment.end_slot()`：推进到窗口截止时刻，得到不可变 `SlotResult`，清除环境持有的运行时引用。未开始或重复结束报错。下一次开始使用新的对象和从零计数的 ERS。
- `SchedulingConfig` 从现有 `config/scheduling.toml` 读取 `max_duration_s`，默认为 1 秒。调度绝对时间从 0 开始，后续时隙从前一个窗口截止时刻开始；固定飞行阶段不加入这条时间线。
- 每个 `SchedulingRuntime` 都绑定有限的 `slot_start` 和 `deadline`；独立构造默认使用 `[0, 1]` 秒窗口，也可显式指定窗口。拒绝超出窗口的推进和提交；提交时刻必须等于当前运行时刻，避免跳过已有事件。
- 推进到截止时刻自动关闭运行时；`finish_slot()` 推进并返回结果，已关闭时重复读取同一结果。关闭后 `submit_dag`、`advance_until`、位置和拓扑更新全部报错。位置/拓扑只允许在提交任务前修改，位置快照复制输入数组。

## 结束语义

截止时刻恰好完成的事件计入成功，截止时刻不再启动新的传输或计算。未完成 DAG 记录 `failed_at=deadline`，未完成子任务标记 `FAILED`，已完成子任务的记录不变。

关闭时清除事件、信道作业和计算队列/核心占用及内部传输绑定。保留旧对象的结果与任务记录供调用方检查，但环境不保留旧对象或旧 DAG，旧引用也不能再推进。Python 对象的内存回收不作为业务生命周期接口。

`SlotResult` 包含时隙起止、各 DAG 标识及完成/失败结果、截止时刻内的传输和计算能耗。进行中的作业按已经执行的时长结算，避免把截止时刻以后的预记能耗算入结果。能耗是所有执行/发送实体的合计，奖励中的 UAV 能耗筛选不在本次范围。

## 验证

以真实环境连续运行两个时隙：第一个窗口存在运行中计算、排队计算和未完成传输，关闭后全部隔离；第二个窗口复用 DAG 标识仍可立即执行。覆盖刚好截止完成、越界返回值、重复开始/结束、关闭后旧引用拒绝操作、非法时间、位置快照及拓扑顺序。十时隙集成测试改用正式 begin/end 接口，完整测试套件回归。
